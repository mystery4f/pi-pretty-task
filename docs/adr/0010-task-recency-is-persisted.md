# Task 的“更新时间”是落盘字段，不是算出来的

每条 Task 带一个 `updatedAt`：创建时等于 `createdAt`，此后只在**状态变化、循环触发、迭代落定、任务结束**时推进；输出文件增长**不算**一次更新。面板按 `updatedAt` 降序排，`tasks.json` 升到 `version: 2`，读到 `version: 1` 或缺这个字段时用 `createdAt` 兜底。

## Considered Options

- **每次读取时算**：`max(createdAt, endedAt, lastFireAt, 最近迭代结束时刻)`，不写盘。省一次 schema 变更，但“什么算变化”散在四个模块里，改一处就悄悄改了排序；而且迭代结束时刻属于 loop 的子记录，读进程任务时还得跨模块拼。
- **输出增长也算更新**：最贴近“最近活动”的直觉，但后台任务每 100 毫秒就在写输出，等于把排序退化成按启动时间排，同时把状态文件写成每秒一次。
- **落盘一个字段（采用）**：写入点集中，排序规则可测、可解释；代价是 schema 升版与一次兼容分支。

## Consequences

- 排序稳定：面板刷新不改变顺序，只有真正的事件才让某一行上浮。
- 每个 kind 都要在自己的状态迁移处调用同一个“touch”，漏掉就会表现为“这行不动”，可被测试直接抓到。
- 旧记录不需要迁移脚本：缺字段就用 `createdAt`，历史任务因此在升级后仍按创建顺序出现。
- 详情页显示绝对时刻加相对时间，行上只显示相对时间 —— 列表要的是“多近”，详情要的是“几点”。
