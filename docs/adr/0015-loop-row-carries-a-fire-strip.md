# 0015 — 循环行内嵌触发的紧凑条带

## 状态
已接受（2026-11-14）

## 背景

ADR 0014 定了「触发是记录，但不是行」。问题是那次触发在循环行上要不要露头：完全不露，人会忘了这个循环刚刚失败过三次；一露就露全部，`Loops` 页会被十秒一次的循环撑爆。

链给了参照：链是一个有限序列，行内直接写 `build → deploy → smoke`，正在跑的那格高亮。循环是无限序列，直接照搬会把行撑破。

## 决策

**循环行右侧内嵌最近 3 次触发的紧凑条带，回车展开看全部。**

- 条带形如 `#43✓ #44✓ #45✗ #46• `：序号 + 结局符号。`✓` 退出 0，`✗` 非零，`•` 仍在跑，被跳过的重叠用 `–`。颜色跟结局走（成功 `success`、失败 `error`、在跑 `accent`、跳过 `muted`）。
- 只放**最近 3 次**，从新到旧或从旧到新都保持固定方向（取「旧 → 新」，新的一直在最右，行不跳）。多出来的不显示，靠展开看。
- 宽度不够时先丢掉条带最左边的几格，绝不折行；再不够就整条不显示，只留 `N fires` 与下次触发时间。
- 回车展开：按时间倒序列出全部触发，每条显示 `#seq 时间 结局 退出码 时长 字节数`；再回车进入该次触发的进程详情（输出、pid、kill 原因）。超过上限的显示 `… N older`。
- 键 `k` 在循环行上是级联终止（ADR 0014），在展开的某一条上只停那一次触发。

## 后果

- 面板需要「最近 N 次触发」的查询，属于根行渲染的一部分，不改变存储。
- 行宽计算多了可丢弃的一段：条带可截断、可整块省略，因此窄终端不会因此折行。
- 状态过滤（`f`）与搜索只作用于根行；一条触发的存在不会让循环行出现在过滤结果里，除非循环本身匹配。
