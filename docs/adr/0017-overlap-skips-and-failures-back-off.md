# 0017 — 重叠跳过、失败退避，不排队

## 状态

已接受（2026-11-14）

## 背景

命令循环按表达式准点触发，但一次触发跑多久不由循环决定。用户写 `10s` 跑一个偶尔要三十秒的脚本，或者一个接口偶发超时连续失败几轮，循环都必须在两种坏结果之间选一个：

- **排队**：到点的触发存下来，等上一个孩子跑完再依次启动。这样「每次触发都跑到」成立，但队列没有上限：脚本卡死十分钟，就等于攒下六十次触发，恢复瞬间一起涌出。用户看到的 `10s` 变成了「尽快补完所有错过」，实际频率和表达式无关，而且补跑的命令大多处理的是已经过时的状态。
- **跳过**：到点时上一个还在跑，这次就不跑了，只记一笔。

ADR 0015 已经决定「触发是记录，但不是行」，记录里带 `outcome`。跳过是这条记录的一个结局，所以「跳过」在存储与面板上本来就有位置，不需要为它另造一个队列。

失败同理：循环失败通常不是瞬时的（接口挂了、脚本崩了），按原节奏重试只是把同一个错误重复打出去，`wakeOnFailure` 的通知也会连着刷屏。

## 决策

**重叠的触发跳过并计数，不排队；连续失败按次数指数退避，成功即归位。**

- 到点时若最近一次触发仍是 `running`，本次触发登记为 `outcome: "skipped"`：没有孩子、没有退出码，`fires` 照常加一，`missedFires` 加一。跳过不改变 `nextFireAt` 之外的东西——表达式仍是用户写的那个。
- 面板行把 `missedFires` 显示成 `N skipped`，条带上对应的格子是 `–`（ADR 0015）。跳过是一条真实记录，不是「什么也没发生」。
- 失败（退出码非零，或孩子根本没起来）后 `consecutiveFailures` 加一，`nextFireAt = max(下个槽位, 本次触发时刻 + 基础间隔 × 2^min(streak, 4))`，上限一小时。四次翻倍之后不再加码：封顶是让循环留在「还会再试」的范围里，而不是把它的下一次推到明天。
- 成功把 `consecutiveFailures` 清零，`nextFireAt` 回到槽位——退避是一次性的延长，不是新的频率。
- 两个计数都随记录落盘，重启后照旧：退避不会被当成「重启就是新的一天」。
- 面板行在计数旁写 `N failed`，下次触发显示 `(backoff)`；详情里 `Failures: N in a row`。行里的 `schedule` 永远是原文，面板不改写表达式去表达退避。

## 后果

- 触发频率的上限由「一次跑多久」决定，不由「错过多少次」决定：慢命令最多占满一个循环，不会攒出一串子进程。
- `fires` 是「到点的次数」，`missedFires` 是「其中没跑的」。两者一起才能回答「这个循环准不准时」，只看 `fires` 会把跳过误读成执行。
- 退避是状态的一部分，不是调度器的一层：`nextFireAt` 就是事实，取值逻辑放在完成触发的地方，读代码的人不必在调度器里找「失败会不会改变节奏」。
- 代价：跳过的那次确实没跑。需要「每次都要跑」的用例应当把表达式写在触发耗时的量级之外，或用 ADR 0013 的链——链的语义就是排队，只是它排队的是有限且由人写下的步骤。
