# 面板分三个标签页，只列根任务，一条链一行

`/tasks` 从“一张混排表”改成三个标签页：`Processes`、`Loops`、`Chains`，用 `1`/`2`/`3` 切换、`tab` 轮转，重开面板回到上次的页。每页只列根任务：链的下一步、cmd loop 的每次触发都不单独占一行，而是在根任务上回车展开。一条链始终是一行，行内显示 `build → deploy → smoke`、正在跑第几步与已用时间。

## Considered Options

- **一张混排表**（现状）：密度最高，键盘导航最省，但 cmd loop 一天几十次触发会把列表灌满，且“这一行是循环还是它的一次触发”必须靠列去分辨。
- **只列根 + 一键分组**：默认扁平、按 `t` 才分组。中间态，但两种模式下的选中位置与滚动位置要各维护一份，容易出界。
- **三个标签页（采用）**：每类字段可以各自安排，列表长度只与“有多少任务”相关，不再与“跑了多少次”相关。代价是多一层导航，以及“东西在哪一页”的记忆负担。
- **链单独一行（叠加在上面）**：`bg_run after:` 产生的步骤在 Processes 页会排成一串互相孤立的行，看不出是一条流水线；把整条链合成一行，进度就写在行上。

## Consequences

- 计数始终是全局的，不随标签页变化 —— 否则“Failed 3”在 Processes 页看不到，只会让人以为没有失败。
- 展开态属于根任务，不进入排序：刷新时顺序不跳，选中位置按 id 保持。
- 链不可单独选中某一步，因此 `k` 在链行上的含义是“从正在跑的那步起，往下整条停掉”；要停单步，先停链再重开。
- 搜索与状态过滤在各页内生效，不跨页：搜索“deploy”在 Loops 页不该命中 Chains 页的行。
- 三页共享同一个键盘模型，新键（`f`/`o`/`/`/`alt+q`）只在页内改变视图，不改变数据。
