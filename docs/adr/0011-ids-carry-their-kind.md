# id 带 kind 前缀：`bg-` 与 `lp-`

进程任务的 id 形如 `bg-1a2cf`，循环任务形如 `lp-1a2cf`，后缀都是 5 位随机字符。id 因此从 6 位变成 8 位，输出文件名跟着变长。

## Considered Options

- **保持 6 位随机、靠面板的 kind 列区分**：宽度最省，但 id 会被抄进聊天、工具返回和通知里，脱离面板那一刻就没有任何线索；模型与用户都得回头查。
- **两字母带连字符（采用）**：`bg-` 与 `lp-` 一眼可读，无需解释，也不依赖任何上下文。
- **更长的人写前缀（例如 `bg50-B`）**：可读性来自人写的那段，随机性反而没了，重名与猜测都变成问题。

## Consequences

- 面板行宽不受影响：id 列本来就是 10 格，8 位刚好放下。
- 输出文件、目录名与日志路径里都出现前缀，读文件时不必先知道它在哪个 kind 的列表里。
- 两个 kind 共用同一个生成器，只是前缀不同；碰撞检查仍按整个会话做，不受前缀影响。
- 旧记录里的 6 位 id 照旧可用，不做重写：id 是引用键，改历史记录等于让旧对话里的引用失效。
