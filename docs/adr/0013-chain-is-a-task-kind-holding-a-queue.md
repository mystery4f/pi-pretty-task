# 0013 — 链是第四种 Task kind，持有一条队列

## 状态
已接受（2026-11-14）

## 背景

需要「按顺序做几件事」的能力：构建完再部署，部署完再冒烟。最初的设想是给 Task 加一个 `parentId`，让链由父子指针隐式推断出来。推敲之后发现两处不足：

- 隐式链没有可寻址的实体：没法给它起名字、没法读回「还剩下哪些没跑」、没法一次停掉整条，也没法在面板里画成一行。
- 父子指针只能表达「谁跟着谁」，表达不了队列本身——插入一格在队尾、游标停在哪一步、剩余几格标成什么状态，都需要一个对象来承载。

因此需要显式的 `Chain` 模型。剩下的问题是：它是 Task 之外的独立记录，还是 Task 的又一种 kind。

## 决策

**`ChainTask` 是 Task 的第四种 kind（`kind: "chain"`），不是独立记录。**

- 面板、排序（`updatedAt` 降序）、摘要行、id 前缀、状态词表都只认「一条 Task」。做成 kind 就自动获得这些，不必再写第二套列表与持久化。
- 一条链有自己的 id（`ch-` 前缀）、名字与时间线，因此可以在面板 `Chains` 页里作为根行出现。

字段：

- `steps: string[]` — 队列，按顺序存**步骤的 task id**，不存任务副本。任务记录仍是输出、状态、退出码的唯一来源；存副本必然与之漂移。
- `cursor: number` — 现在跑第几格。
- `status` — 推进时落盘，行上直接读，不每次现算。

约束：

- 步骤只能是 `kind: "process"` 的任务。Llm loop 排进队列等于同时受 cron 与队列两套时钟支配，是没想清楚的语义，明确不做。
- 一次只跑一格。当前格结束：退出码 0 → `cursor + 1` 并启动下一格；非零 → 链 `failed`，余下各格 `skipped`；用户终止 → 余下各格 `stopped`。
- 步骤是 chain 的子记录：`parentId = <chainId>`。`Chains` 页只列 `kind === "chain"` 的行，`Processes` 页过滤掉 `parentId` 非空的步骤，避免同一件事出现两次。
- `bg_run({ after })` 双语义：传任务 id 时挂到该任务所属链的队尾，传 `ch-` id 时直接追到该链的队尾（允许在链运行中追加）。
- 没有隐式链：不属于任何链的任务，不会被当成「只含一格的链」展示。

## 后果

- 存储文件的版本再升一级，`tasks` 数组里多出 `chain` 记录；旧文件没有这种记录，直接兼容。
- 事件与通知需要区分「链结束」与「格结束」：格结束照旧发任务事件，链结束时只多一条链粒度的状态。
- 面板的 `Chains` 页与 `Loops` 页都是「根 + 展开子记录」的同一套渲染，只是展开内容不同。
- 将来若要支持分支或并行（DAG、fan-out），需要新决策：本 ADR 明确链是线性的，且一次一步。
