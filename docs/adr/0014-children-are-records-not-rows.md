# 0014 — 子记录是记录，不是行

## 状态
已接受（2026-11-14）

## 背景

ADR 0012 定了「三页、只列根」。但没有写清一个推论：一次 cmd loop 触发、一格链步骤，在存储与界面上分别算什么？如果只写「不单独占一行」，实现时很容易走成「触发只是循环身上的一段文字」——那样就没有独立 id、没有自己的输出文件、没法单独查。

## 决策

**触发与步骤都是普通 Task，只是不占行。**

- 一次触发 = 一个 `kind: "process"` 的 Task，`parentId` 指向所属循环；一格链步骤同理，指向所属链。它有独立 id、独立输出文件、独立退出码与 kill 原因。
- 它们**不进任何页的列表**：`Processes` 页过滤掉所有 `parentId` 非空的 Task，`Loops` 页列出 `cmd-loop`/`llm-loop` 根，`Chains` 页列出 `chain` 根。
- 它们**能被直接查询**：`bg_status`、`bg_logs`、`bg_grep`、`bg_wait` 接受触发/步骤的 id，与普通任务完全一样。展开只是给人看的入口，不是唯一入口。
- **计数包含子记录**：正在跑的触发算进 `Running`，失败的触发算进 `Failed`。否则「Failed 0」会掩盖一个每十秒失败一次的循环。
- **`k` 是级联的**：在循环行上按 `k`，先让循环不再排下一次，再停当下正在跑的那次触发；在链行上按 `k`，从正在跑的那格起，把余下各格标为 `stopped`。
- **展开的选中位置不参与排序**：刷新时根行顺序按 `updatedAt` 排，展开里选中的那一条按 id 保持，不因新触发到来而跳走。

## 后果

- 存储里 Task 数量随触发增长，因此保留策略（票 #28）与「循环只留最近 N 次触发」（ADR 0007 的同类上限）必须一起存在。
- 面板渲染分成两层：根行与展开行用同一套行渲染，但展开行不参与排序、不可作为排序键，也不触发根级动作（`R`/`c` 只作用于根）。
- 任何需要「所有任务」的地方（计数、事件、保留策略）都必须显式决定要不要包含子记录，默认包含，只有列表排除。
