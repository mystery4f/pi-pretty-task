# 🔍 Observation: GIF 里"看不见"的新功能属于节奏问题

pi-pretty-task 的前台命令改道（ADR-0020）进 README GIF 后，用户反馈"没看到快捷键和新功能"。实际核对方式不是看脚本输出，而是把 gif 的真实像素解出来：写 .tmp 脚本用 playwright-core 打开 file:// 页面（ImageDecoder 只在 secure context 可用，about:blank 里是 undefined，file:// 下可用），把 gif 的 base64 传进 page.evaluate，用 ImageDecoder 逐帧 draw 到 canvas 导出 PNG，再肉眼读帧。结果第 0 帧就有底栏提示 `↪ 1 command in front · ctrl+shift+b moves it to the background`，第 1 帧提示消失、任务进列表。真问题是节奏：两帧各 1.1 秒，整段 16 秒循环，从中间进入只能看到旧的 walk 帧。修法是 writeGif 支持逐帧 delays，改道两帧各停 2.4 秒（scripts/preview/shoot.mjs + preview.mjs，提交 c6ec55a）。另一个坑：改延时后文件字节数不变（GCE 只是把 1100 改成 2400，字节数相同），所以"raw 返回 279200 与本地一致"根本不能证明远端是新的；要比 md5 或解析每帧 delay。迁移结论：断言一张动图/图片的内容，必须解码像素或校验 md5，不能凭"文件被我覆盖了/大小对得上"。
